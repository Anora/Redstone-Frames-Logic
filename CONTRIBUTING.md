# Contributing to Redstone Frames & Logic (RFL)

Thank you for your interest in contributing to **Redstone Frames & Logic (RFL)**!
Contributions are welcome, but please read the following guidelines before submitting changes.

---

🧭 Project Philosophy

RFL is built around:
- Deterministic logic behavior
- A node-based logic system
- Clean separation between Minecraft blocks and logic implementation

Please try to keep contributions aligned with these goals.

---

🔁 Contribution Workflow

1. Fork the repository
   Create your own fork of the project on GitHub.

2. Create a feature branch
   Work on a new branch in your fork:
```bash
git checkout -b my-feature

3. Make your changes

    Keep commits focused and clear

    Avoid unrelated refactors

    Test changes in-game where applicable

4. Open a Pull Request

Submit a pull request (PR) targeting the master branch.

All changes must go through a PR — direct pushes are disabled.
✅ Review & Approval

    At least one approval is required before merging

    The project maintainer reviews all PRs

    Feedback or requested changes may be given before approval

Please be patient — this is an active but evolving project.

🛠️ What to Contribute

Good contribution ideas include:

    New logic gate blocks using existing nodes

    Bug fixes or performance improvements

    Documentation improvements

    Test cases or debug tooling

    Code cleanup that improves clarity without changing behavior

If you’re unsure about a change, feel free to open an issue first.
🚫 What Not to Do

Please avoid:

    Large refactors without discussion

    Breaking public APIs without a clear reason

    Adding logic directly into blocks (logic belongs in nodes)

    Introducing block entities unless absolutely necessary

📬 Questions or Ideas?

If you’re unsure about something:

    Open an issue

    Start a discussion

    Ask before doing major work

Thanks for helping improve RFL!
